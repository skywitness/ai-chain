## 一句話解釋

<Term id="llm">大型語言模型</Term>（Large Language Model，LLM）是一個讀過海量文字的超大型<Term id="neural-network">神經網路</Term>。它的核心本領只有一個：**根據前面的文字，預測下一個 <Term id="token">Token</Term>（字詞片段）最可能是什麼**。把這個動作重複幾百、幾千次，就能寫出文章、回答問題，甚至寫程式。ChatGPT、Claude、Gemini 這些聊天服務，背後都是 LLM。

## 生活化比喻

<Callout type="analogy" title="一位讀遍整座圖書館的文字接龍高手">

手機輸入法打出「謝謝」，下一個字常會跳出「你」或「大家」，這是依據你平常怎麼打字來猜。LLM 做的是同一件事的超級加強版：

- **讀過的文字多到難以想像**：3Blue1Brown 估算，一般人若想讀完 GPT-3 訓練用的文字，就算一天 24 小時不停地讀，也要讀超過 2,600 年<Cite k="3b1b-llm" />。
- **不是背答案，而是記住「語感」**：它沒有一個可以查詢的資料庫，而是把讀到的規律壓縮進數千億個<Term id="parameter">參數</Term>裡。就像一位博覽群書的人憑印象說話，大部分時候頭頭是道，偶爾也會把記錯的事講得斬釘截鐵。

所以，LLM 比較像「很會接話的人」，而不是「百科全書」。記住這個差別，就能理解它的強項與弱點。

</Callout>

## 原理

### 第一步：把文字切成 Token

模型不是一個字一個字地讀，而是先用<Term id="tokenizer">分詞器</Term>把文字切成 Token。一個 Token 可能是一個英文單字、單字的一部分、一個標點，或是一兩個中文字。Google 的開發文件指出，對 Gemini 模型來說，1 個 Token 大約等於 4 個英文字元，100 個 Token 約是 60 到 80 個英文單字<Cite k="gemini-tokens" />；DeepSeek 則估計，1 個中文字約等於 0.6 個 Token<Cite k="deepseek-tokens" />。每個模型的切法不同，比例也不一樣。

每個模型都有一份固定的詞彙表，例如 GPT-3 的詞彙表有 50,257 個 Token<Cite k="3b1b-gpt" />。切好的每個 Token 會換成一長串數字，也就是<Term id="embedding">嵌入向量</Term>，神經網路才能計算。Token 同時是 AI 服務計費與計算容量的單位，細節見<LearnLink id="tokens-and-embeddings">Token 與嵌入向量</LearnLink>。

### 第二步：預測下一個 Token

輸入「台灣最高的山是」，模型不會只給一個答案，而是替詞彙表裡**每一個** Token 打分數，再用 <Term id="softmax">Softmax</Term> 換成機率。舉例來說（數字僅為示意）：「玉」可能占九成以上，「雪」占幾個百分點，其他成千上萬個 Token 分掉剩下的一點點。

接著模型挑出一個 Token 接在句子後面，再把加長的句子整段送回去，預測下一個。3Blue1Brown 指出，模型不一定每次都選機率最高的字，偶爾挑機率較低的字，寫出來的文字反而比較自然<Cite k="3b1b-llm" />。

這就是聊天機器人的回答總是「一個字一個字冒出來」的原因：每多產生一個 Token，整個網路就要再算一次。這個使用模型的過程叫做<Term id="inference">推論</Term>，也是 AI 晶片最主要的工作之一。

### Transformer：一次看懂整段話

要猜得準，模型必須理解上下文。「蘋果發表新手機」和「這顆蘋果很甜」裡的「蘋果」，意思完全不同。2017 年 Google 研究人員提出的 <Term id="transformer">Transformer</Term> 架構<Cite k="transformer-2017" />，靠<Term id="attention">注意力機制</Term>讓每個 Token 都能回頭看句子裡的其他 Token，判斷哪些字和自己最相關。在此之前，多數語言模型一次只處理一個字；Transformer 則能同時處理整段文字<Cite k="3b1b-llm" />，非常適合交給 GPU 平行計算，模型才得以一路放大。今天主流的 LLM 大多建立在這個架構上，詳見<LearnLink id="transformer-and-attention">Transformer 與注意力機制</LearnLink>。

### 從「接龍高手」到「對話助理」

LLM 的養成分成兩大階段。

**第一階段是預訓練：大量閱讀。**<Term id="pretraining">預訓練</Term>時，模型拿海量文字做「猜下一個字」的練習：給它一段文字、讓它猜接下來的字，猜錯就用反向傳播微調所有參數，讓正確答案的機率高一點<Cite k="3b1b-llm" />。這個練習重複數兆次，模型就從語法、常識一路學到寫程式。預訓練用的資料量成長得非常快：

**第二階段是後訓練：學會當助理。**只做過預訓練的模型很會接話，卻不一定會好好回答問題。<Term id="post-training">後訓練</Term>先用人類寫好的示範對話做<Term id="sft">監督式微調（SFT）</Term>，再請人替模型的多個回答排名，用<Term id="rlhf">人類回饋強化學習（RLHF）</Term>調整模型。OpenAI 在 2022 年發表的研究發現，經過這套流程、只有 13 億參數的 InstructGPT，回答比 1,750 億參數的 GPT-3 更受評分者青睞<Cite k="instructgpt" />。同年 11 月 30 日，OpenAI 推出 ChatGPT<Cite k="chatgpt-launch" />，讓 LLM 走進大眾生活。

### 「大」到底有多大

「大型」指的是參數多、訓練資料多，以及一次能讀進的內容多，後者稱為<Term id="context-window">上下文視窗</Term>。比較 2020 年的 GPT-3 與 2026 年的<Term id="open-weights">開放權重</Term>模型 DeepSeek-V4-Pro：

| 項目 | GPT-3（2020） | DeepSeek-V4-Pro（2026） |
|---|---|---|
| 參數量 | 1,750 億 | 1.6 兆（每個 Token 只啟用 490 億） |
| 預訓練資料 | 3,000 億個 Token | 逾 32 兆個 Token |
| 上下文視窗 | 2,048 個 Token | 100 萬個 Token |

表中數字來自 GPT-3 論文<Cite k="gpt3" />與 DeepSeek 官方模型卡<Cite k="deepseek-v4" />，後者是 DeepSeek 在 2026 年 4 月發表的 V4 系列預覽版。DeepSeek-V4-Pro 採用 <Term id="moe">MoE</Term>（混合專家）架構，每個 Token 只動用一小部分的<Term id="active-parameters">啟用參數</Term>。100 萬個 Token 依 DeepSeek 的比例換算，約是 167 萬個中文字；Google 文件也顯示，Gemini 模型的上下文視窗達 1,048,576 個 Token<Cite k="gemini-tokens" />。不過，並非每家公司都公開這些數字，例如 OpenAI 在 GPT-4 技術報告中就表明不公開模型大小<Cite k="gpt4" />。

最需要留意的是<Term id="hallucination">幻覺</Term>。2025 年一篇由 OpenAI 研究人員參與的論文舉例：研究者問開放權重模型 DeepSeek-V3「論文第一作者的生日是哪天」，並要求「知道才回答」，結果模型三次給了三個不同的錯誤日期。論文認為，原因之一是訓練與評測方式都在獎勵「不確定也要猜」，而不是坦承不知道<Cite k="hallucination" />。所以，LLM 給的事實、數字與引用，重要時一定要查證。

<DeepDive title="深入一點：分數怎麼變成機率？每個 Token 又要花多少運算？">

模型最後會替詞彙表中的每個 Token i 算出一個分數 zᵢ，Softmax 再把這些分數轉成加總為 1 的機率：

<MathTeX tex="p_i = \exp(z_i / T) \;/\; \sum_j \exp(z_j / T)" display label="第 i 個 Token 的機率，等於 e 的 z_i 除以 T 次方，再除以所有 Token 同樣數值的總和" />

分數越高，機率越大，但其他 Token 仍保有一點機會。公式中的 T 叫做「溫度」：T 越大，機率分布越平均，回答越多變；T 越小，最高分的 Token 越占優勢；T 等於 0 時，模型每次都選最高分的那一個<Cite k="3b1b-gpt" />。這就是有些 AI 服務提供溫度設定的原因：查資料、寫程式時調低，寫故事、發想點子時調高。

**每個 Token 的運算成本。** EleutherAI 整理的經驗法則是，模型每處理一個 Token，大約需要「2 × 參數量」次浮點運算<Cite k="eleuther" />；MoE 模型則以啟用參數計算。以 DeepSeek-V4-Pro 為例，粗估每個 Token 約需 2 × 490 億 ≈ 980 億次運算（未計入注意力機制本身的額外運算，上下文越長，這部分越多）。一篇 1,000 字的中文回答，依 DeepSeek 的比例約 600 個 Token，合計約 59 兆次運算。

**每個 Token 的價格。** 模型以 API 提供時，多半依 <Term id="token-pricing">Token 計價</Term>。DeepSeek 官方定價頁列出，V4-Pro 在尖峰時段每 100 萬個輸出 Token 收 3.96 美元，輸入（未命中快取）收 1.32 美元<Cite k="deepseek-pricing" />。換算下來，上面那篇 600 個 Token 的回答，輸出費用約 0.24 美分。單次很便宜，但用量極大：Alphabet 執行長在 2026 年 7 月的法說會上表示，光是 Google 的模型 API，每分鐘就要處理約 220 億個 Token，高於前一季的 160 億個<Cite k="alphabet-q2-2026" />。累積起來，就是龐大的算力需求。
