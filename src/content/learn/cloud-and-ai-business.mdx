## 一句話解釋

**<Term id="cloud-computing">雲端運算</Term>就是「把電腦租給別人用」：企業不必自己買伺服器、蓋機房，而是按用量付費。進入 AI 時代，雲端業者出租的主角變成 <Term id="gpu">GPU</Term> 算力，模型公司則把 AI 的能力切成一個個 <Term id="token">Token</Term> 來賣，或包成每月訂閱。** 看懂這門生意，就能理解為什麼科技巨頭願意每一季投入數百億美元蓋<Term id="datacenter">資料中心</Term>。

## 生活化比喻

<Callout type="analogy" title="想吃一頓飯，有四種方式">

- **自己蓋廚房**：買地、買爐具、請廚師，一次花很多錢，但完全自己掌控。這就像企業自己買 GPU、蓋資料中心。
- **租共享廚房**：設備由房東準備，按小時付租金。這是向雲端業者租用 GPU，按小時計費。
- **叫外送**：點多少付多少。這是透過 <Term id="api">API</Term> 呼叫模型，按 Token 用量計價。
- **吃到飽**：每月固定付一筆錢，在店家規定的份量內想吃就吃。這是 ChatGPT、Claude 這類 AI 助理的月費訂閱，通常也設有用量上限。

越往下走，使用者越省事，但也把越多利潤交給提供服務的業者。AI 產業的商業模式，就是一群公司在這四種「吃法」之間分工合作。

</Callout>

## 原理：AI 的錢怎麼流動

### 一條從使用者流向晶片的金流

<FlowSteps title="AI 產業的金流" steps={[{ title: "使用者與企業", detail: "付月費訂閱或 API 使用費" }, { title: "AI 應用", detail: "把模型包裝成產品" }, { title: "模型公司", detail: "訓練與提供模型" }, { title: "雲端業者", detail: "出租 GPU 算力" }, { title: "硬體供應鏈", detail: "晶片、伺服器、電力" }]} />

每一層都向下一層付錢：使用者付錢給 AI 應用，應用付 API 費給模型公司，模型公司向雲端租用算力，雲端業者再拿錢去買晶片、伺服器與電力。以 <CompanyChip id="openai">OpenAI</CompanyChip> 為例，它在 2026 年 3 月表示每月營收約 20 億美元，而它的算力來自微軟、甲骨文、AWS、CoreWeave 與 Google Cloud 等多家雲端業者<Cite k="oa-funding" />。

### 四種收費方式

| 收費方式 | 怎麼計價 | 實際例子 |
|---|---|---|
| 月費訂閱 | 每人每月固定費用 | Claude Pro 月繳 20 美元<Cite k="claude-plans" /> |
| 按 Token 計價 | 依輸入與輸出的 Token 數量 | Claude Sonnet 5.5 每百萬輸入 Token 2 美元、輸出 10 美元<Cite k="claude-pricing" /> |
| GPU 時租 | 每顆 GPU 每小時 | Lambda 的 H100（8 卡機型）每顆每小時 3.99 美元<Cite k="lambda-pricing" /> |
| 席位加用量 | 每位員工月費，再加實際用量 | Claude Enterprise 每席每月 20 美元，用量另依 API 價格計算<Cite k="claude-plans" /> |

**訂閱**是消費者最熟悉的模式。OpenAI 在 2026 年 3 月表示，ChatGPT 的付費訂閱數超過 5,000 萬<Cite k="oa-funding" />；企業端則常按「席位」收費，例如<CompanyChip id="microsoft">微軟</CompanyChip>的 Microsoft 365 Copilot 付費席位已超過 3,000 萬個<Cite k="msft-fy26-q4" />。這種按月收費、透過網路使用的軟體，稱為 <Term id="saas">SaaS</Term>（軟體即服務）。

**按 Token 計價**是開發者與企業最常用的方式，業界稱為<Term id="token-pricing">Token 計價</Term>，就像水電費按度數計價。輸出 Token 的單價通常是輸入的好幾倍，因為輸入的文字可以一次平行讀完，輸出卻得一個接一個產生，每寫出一個 Token 都要把整個網路再算一次（見<LearnLink id="what-is-llm">大型語言模型是什麼</LearnLink>）。這門生意的規模可以用 Token 處理量來想像：OpenAI 在 2026 年 3 月表示，它的 API 每分鐘處理超過 150 億個 Token<Cite k="oa-funding" />；Google 在 2026 年 7 月表示，Gemini 模型每分鐘處理 220 億個 API Token<Cite k="goog-q2-2026" />。兩家公布的時間點不同，不宜直接比大小。

**GPU 時租**又稱 <Term id="gpu-as-a-service">GPUaaS</Term>（GPU 即服務），客戶多半是要自己訓練或部署模型的公司。以 <CompanyChip id="lambda">Lambda</CompanyChip> 的隨選方案為例，較新的 B200 每顆每小時 6.69 美元，上一代的 H100 則是 3.99 美元<Cite k="lambda-pricing" />；若簽較長期的合約或租用大型叢集，價格另外議定。

**廣告與電商**是最新加入的收入來源。OpenAI 財務長在 2026 年 1 月撰文說明，公司的商業模式包括消費者與團隊訂閱、由廣告與電商支撐的免費方案，以及按用量計價的 API，未來還可能出現授權與按成果計價等模式<Cite k="oa-business" />。到了 2026 年 3 月，OpenAI 的廣告試行計畫不到六週，年化營收就超過 1 億美元<Cite k="oa-funding" />。

### 雲端三巨頭與新雲

全球雲端市場由三家<Term id="hyperscaler">超大規模業者</Term>主導：亞馬遜（Amazon）的 AWS、微軟的 Azure，以及 Google Cloud。研究機構 Synergy Research 估計，2026 年第二季全球雲端基礎設施服務營收達 1,434 億美元，<Term id="yoy">年增</Term> 43%，是八年來最快的成長；三家市占率分別約 28%、20%、15%，而生成式 AI 專屬的雲端服務更年增 165%<Cite k="synergy-q2-2026" />。

### 模型公司：營收跟著算力走

模型公司是雲端最大的客戶之一。OpenAI 財務長公開了一組數字，說明營收幾乎和可用算力同步成長；這裡的算力以資料中心可用的電力容量計算，單位是 <Term id="gigawatt">GW</Term>（十億瓦）<Cite k="oa-business" />：

| 年份 | OpenAI 可用算力 | 年化經常性營收 |
|---|---|---|
| 2023 | 0.2 GW | 20 億美元 |
| 2024 | 0.6 GW | 60 億美元 |
| 2025 | 約 1.9 GW | 逾 200 億美元 |

這裡的 <Term id="arr">ARR</Term>（年化經常性營收）是把目前每月的經常性收入乘以 12，用來描述成長快速的公司。她也認為，如果過去這幾年有更多算力，客戶採用與營收原本可以成長得更快<Cite k="oa-business" />。另一家模型公司 <CompanyChip id="anthropic">Anthropic</CompanyChip> 的年化營收，從 2026 年 2 月的 140 億美元<Cite k="an-series-g" />，增加到同年 5 月的逾 470 億美元<Cite k="an-series-h" />。

模型公司也透過雲端「上架」賣模型。Anthropic 的 Claude 同時在 AWS、Google Cloud 與 Microsoft Azure 三大平台提供<Cite k="an-series-h" />，企業可以在熟悉的雲端上直接呼叫，雲端業者也因此多賺一份平台收入。

### 先花錢、後收錢：巨額資本支出

要賣算力，得先買 GPU、蓋資料中心。2026 年第二季，三大雲端業者的<Term id="capex">資本支出</Term>都比一年前大幅增加：

<BarChart title="2026 年第二季資本支出（購置不動產與設備）" unit="十億美元" data={[{ label: "亞馬遜", value: 54.2 }, { label: "Alphabet", value: 44.9 }, { label: "微軟", value: 35.8 }]} source={["amzn-q2-2026", "goog-q2-2026", "msft-fy26-q4"]} note="截至 2026 年 6 月 30 日的單季現金支出；微軟為 FY2026 第四季" />

三家一季合計約 1,349 億美元；一年前同一季分別是 322 億、224 億與 171 億美元，合計約 717 億美元，一年內接近翻倍<Cite k="amzn-q2-2026" /><Cite k="goog-q2-2026" /><Cite k="msft-fy26-q4" />。

這些錢買來的伺服器與廠房，會在未來幾年以<Term id="depreciation">折舊</Term>的方式逐年攤成成本。也就是說，雲端業者今天先付錢，期待未來幾年的 AI 收入把錢賺回來。短期內，自由現金流會承受壓力：亞馬遜近四季購置設備的淨支出比一年前多了 661 億美元，使近四季的<Term id="free-cash-flow">自由現金流</Term>從一年前流入 182 億美元，轉為流出 76 億美元<Cite k="amzn-q2-2026" />。

業者願意這樣投資，一個重要理由是手上已經有大量簽好的合約。財報中的 <Term id="rpo">RPO</Term>（剩餘履約義務）代表客戶已經簽約、但還沒認列的營收：微軟的商業 RPO 達 6,780 億美元、年增 84%<Cite k="msft-fy26-q4" />，甲骨文也有 6,640 億美元<Cite k="orcl-q1-fy27" />。不過，合約要先蓋好資料中心、交付算力，才會變成營收；如果 AI 應用的收入成長跟不上，這些投資就可能變成沉重的負擔，這也是市場討論 <TrendLink id="ai-infra-financing-bubble">AI 基礎設施融資與泡沫風險</TrendLink>的焦點。

<DeepDive title="深入一點：一顆 GPU 每秒要產出多少 Token 才回本？">

用前面的價格做一個簡化的試算。假設一家公司向雲端租一顆 B200，每小時 6.69 美元<Cite k="lambda-pricing" />，拿來提供模型服務，每百萬個輸出 Token 收 10 美元，也就是 Claude Sonnet 5.5 的價格<Cite k="claude-pricing" />。先忽略輸入 Token、人力與其他成本，每小時的營收是：

<MathTeX tex={"\\text{每小時營收}=\\text{每秒 Token 數}\\times 3600\\times\\text{每個 Token 的價格}"} display label="每小時營收等於每秒產出的 Token 數乘以 3600 秒再乘以每個 Token 的價格" />

每個 Token 的價格是 10 ÷ 1,000,000 ＝ 0.00001 美元。要賺回 6.69 美元的租金，每小時至少要賣出 6.69 ÷ 0.00001 ＝ 669,000 個 Token，換算成**每秒約 186 個 Token**。

這個門檻能不能跨過，取決於兩件事：

1. **能不能同時服務很多人**：推論伺服器會用<Term id="batching">批次處理</Term>，讓一顆 GPU 同時替許多使用者產生 Token，總產出就能比只服務一個人高出許多。這也是<Term id="inference">推論</Term>服務能賺錢的關鍵。
2. **使用率高不高**：如果 GPU 有一半時間閒置，忙碌時段就得產出兩倍的 Token 才能打平。這也是雲端業者偏好簽多年期合約的原因：先確定有人用，再買 GPU。

一般來說，模型越大，每產生一個 Token 要做的運算越多，一顆 GPU 能賣出的 Token 就越少，單價也就越高。廠商通常不公開模型大小，但價格差距可以看出定位：Anthropic 最高階的 Claude Fable 5.1，輸出價格是每百萬 Token 50 美元，是 Sonnet 5.5 的 5 倍<Cite k="claude-pricing" />。反過來說，演算法與硬體一進步，服務成本下降，價格也會跟著降。Anthropic 表示 Opus 5.5 服務所需的運算比 Opus 5 少，因此定價降低 20%<Cite k="claude-opus-55" />：

<BarChart title="Claude Opus 系列的輸出價格" unit="美元／百萬 Token" data={[{ label: "Opus 4.1", value: 75 }, { label: "Opus 4.5", value: 25 }, { label: "Opus 5", value: 25 }, { label: "Opus 5.5", value: 20 }]} source="claude-pricing" keepOrder note="節錄部分版本，依推出先後排列；Opus 4.6 到 4.8 的輸出價格同為 25 美元。皆為官方定價頁列出的標準價格" />

OpenAI 也採取類似的策略：前沿模型在高階硬體上訓練，大量的推論工作則改放到成本較低的基礎設施上<Cite k="oa-business" />。對整條產業鏈來說，這代表 AI 的需求不只取決於「模型多聰明」，也取決於「每個 Token 能多便宜」。
