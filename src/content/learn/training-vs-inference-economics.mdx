## 一句話解釋

<Term id="training">訓練</Term>是「做出」模型的一次性投資：運算量大約等於 6 × 參數量 × 訓練 Token 數，必須在幾週到幾個月內集中投入成千上萬顆 GPU。<Term id="inference">推論</Term>是「使用」模型的持續成本：每產生一個 <Term id="token">Token</Term> 大約要做 2 × 參數量次運算，用的人越多，帳單就越大。前者像研發費用，後者像每賣出一份商品的成本，兩者需要的硬體與商業邏輯都不一樣。

## 生活化比喻

<Callout type="analogy" title="研發一道招牌菜，與每天出餐">

想像一家連鎖餐廳推出新的招牌菜：

- **訓練像研發菜色**：主廚團隊關在實驗廚房好幾個月，試做上千次、用掉大量食材，最後得到的只是一份食譜（模型的權重）。這筆錢不管之後賣出幾份，都已經花掉了。
- **推論像每天出餐**：菜單上線後，每來一位客人，廚房就要開火做一份。單份成本不高，但一天賣出幾百萬份，累積起來可能比研發還貴。
- **一鍋炒十份，比一份一份炒便宜得多**：這就是推論時的批次處理。
- **預期客人很多時，值得多花研發時間把食譜改得更簡單**：做菜步驟少一點，每份的成本就低一點。這對應到「把小模型訓練得更久」的策略。

</Callout>

## 原理

### 訓練的帳：6ND

EleutherAI 整理的經驗公式是：訓練一個模型的總運算量 C，約等於 6 × 參數量 N × 訓練 Token 數 D。其中前向傳播（讓資料流過模型、算出預測）約占 2ND，反向傳播（算出每個<Term id="parameter">參數</Term>該怎麼調整）約占 4ND<Cite k="eleuther" />。

<MathTeX tex="C \approx 6 N D" display label="訓練運算量約等於 6 乘以參數量乘以訓練 Token 數" />

用 Meta 的 Llama 3 論文驗算（論文中的結果皆屬於 2024 年 7 月發布的 Llama 3.1 系列）：旗艦模型有 4,050 億個參數，以 15.6 兆個 Token <Term id="pretraining">預訓練</Term>。代入公式，6 × 4,050 億 × 15.6 兆 ≈ 3.8 × 10²⁵ 次運算，和論文公布的 3.8 × 10²⁵ <Term id="flops">FLOPs</Term> 一致<Cite k="llama3" />。這個數字有多大？就算一顆 H100 的 16 位元稠密算力每秒約 989 兆次<Cite k="nvidia-h100" />，也要算上 1,200 多年。

所以訓練一定要「人多」。Llama 3 最多同時用了 1.6 萬顆 H100，但並不是每一顆都能全速運轉：衡量實際效率的<Term id="mfu">模型運算使用率（MFU）</Term>為 38–43%<Cite k="llama3" />，也就是峰值算力有一半以上沒有變成有用的訓練運算：GPU 會花時間等資料、等其他 GPU 傳來結果，也要處理矩陣乘法以外的工作。大型叢集也很容易出狀況：在 54 天的觀察期間，Llama 3 的訓練遇到 419 次非預期中斷，其中 58.7% 和 GPU 有關，靠著自動化的故障處理，有效訓練時間才維持在 90% 以上<Cite k="llama3" />。

為什麼一定要切給這麼多 GPU？除了算力，還有記憶體。用常見的混合精度搭配 AdamW 優化器訓練時，每個參數要存權重、梯度與優化器狀態，合計約 16 位元組<Cite k="eleuther" />。4,050 億個參數就是約 6.5 TB，而一顆 H100 只有 80 GB 的 <Term id="hbm">HBM</Term><Cite k="nvidia-h100" />，光是放下這些狀態就要 80 多顆。因此訓練要把資料切給不同 GPU（<Term id="data-parallelism">資料平行</Term>）、把模型本身切開（<Term id="tensor-parallelism">張量平行</Term>），再用 <Term id="all-reduce">All-Reduce</Term> 讓所有 GPU 交換、平均梯度。

<Scene3D id="train-infer" variant="training" caption="訓練視角：小批次資料分給多張 GPU，各自前向傳播、算出損失、反向傳播算梯度，再以環狀 All-Reduce 交換並平均梯度，所有副本做出相同的更新。切換到推論視角，可以看到批次處理、Prefill／Decode 與 KV Cache。GPU 數量與曲線皆為示意。" />

### 把 GPU 時數換成錢

最直接的估算方式是「GPU 時數 × 每小時租金」。DeepSeek 在 DeepSeek-V3 的技術報告中公開了這筆帳：完整訓練用了 278.8 萬個 H800 GPU 小時，以每 GPU 小時 2 美元的租金計算，約 557.6 萬美元；報告也強調，這只是正式訓練那一次的成本，不含先前的研究與實驗<Cite k="deepseek-v3" />。

Meta 的模型卡顯示，Llama 3.1 405B 的訓練用了 3,084 萬個 H100 GPU 小時<Cite k="llama31-card" />。若套用 DeepSeek 的 2 美元假設，約 6,200 萬美元；若改用 Lambda 在 2026 年 10 月的 H100 隨選牌價（每 GPU 小時 3.99 美元）<Cite k="lambda-pricing" />，約 1.2 億美元。這兩個數字是本站的粗估，只計算 GPU 租金，用來感受數量級。

真實的開發成本遠不只最後一次訓練。研究機構 Epoch AI 在 2024 年的分析中估計，GPT-4、Gemini Ultra 等前沿模型的開發成本裡，硬體占 47–67%、研發人員占 29–49%、能源只占 2–6%；前沿模型最終訓練的硬體與能源攤提成本，自 2016 年起每年成長約 2.4 倍，並推估若趨勢延續，最大型的訓練在 2027 年將超過 10 億美元<Cite k="epoch-train-cost" />。對模型公司來說，訓練比較像一筆研發投資，或是租用 <Term id="gpu-as-a-service">GPU 算力服務</Term>的大額支出，而不是隨營收增減的成本。

### 推論的帳：每個 Token 都要付錢

推論只需要前向傳播，所以每產生一個 Token，約需 2 × 參數量次運算<Cite k="eleuther" />。這也是 <Term id="moe">MoE</Term>（混合專家）架構在經濟上的意義：DeepSeek-V3 總共有 6,710 億個參數，但每個 Token 只啟用其中 370 億個<Cite k="deepseek-v3" />。以<Term id="active-parameters">啟用參數</Term>計算，每個 Token 約 740 億次運算，只有同樣大小稠密模型的 18 分之 1 左右。不過，全部 6,710 億個參數仍要放在記憶體裡，所以 MoE 省下的是運算量，而不是記憶體容量。

推論又分成兩個階段。<Term id="prefill">Prefill</Term> 一次讀完整段提示詞，可以大量平行計算，屬於「算力受限」；Google 研究者在 5,400 億參數的 PaLM 上，大批次處理輸入時的運算使用率達 76%<Cite k="pope-inference" />。<Term id="decode">Decode</Term> 則是一個 Token 接一個 Token 產生，每一步都得把權重從記憶體讀一遍；同一篇研究在小批次生成時，把每個 Token 的延遲壓到 29 毫秒，用的方法之一正是把權重量化成 8 位元整數，減少每一步要讀的資料量<Cite k="pope-inference" />。<LearnLink id="gpu-architecture">GPU 與 AI 加速器架構</LearnLink>提到的<Term id="memory-wall">記憶體牆</Term>，在 Decode 階段最明顯。

推論的成本可以用一個簡單的公式表示：每百萬個 Token 的成本 c，等於 GPU 每小時成本 p，除以每小時能產生的 Token 數，再乘以一百萬（r 是每秒產生的 Token 數）。

<MathTeX tex="c = p / (3600 \times r) \times 10^6" display label="每百萬 Token 成本等於每小時 GPU 成本除以每小時產生的 Token 數，再乘以一百萬" />

關鍵在 r。以 80 億參數的 Llama 3.1 8B 為例，用 16 位元儲存時權重約 16 GB；放在記憶體頻寬每秒 3.35 TB 的 H100 上<Cite k="nvidia-h100" />，讀一遍權重約需 4.8 毫秒。<Term id="batching">批次處理</Term>讓讀一次權重就能同時替許多請求各產生一個 Token，於是：

| 同時處理的請求數 | 每秒產生的 Token 數（理想上限） | 每百萬 Token 的 GPU 租金 |
|---|---|---|
| 1 | 約 210 | 約 5.3 美元 |
| 8 | 約 1,680 | 約 0.66 美元 |
| 64 | 約 13,400 | 約 0.08 美元 |

這張表是本站以 H100 頻寬規格與 Lambda 每小時 3.99 美元的隨選價格<Cite k="lambda-pricing" />推算的理想化示意，沒有計入 KV Cache 讀取、注意力運算與排程開銷，實際<Term id="throughput">吞吐量</Term>會更低。但方向很清楚：同一張 GPU、同一個模型，批次越大，每個 Token 的成本就越低。vLLM 的論文也指出，高吞吐量的服務必須一次批次處理足夠多的請求；難處在於每個請求的 <Term id="kv-cache">KV Cache</Term> 都很大，而且會隨對話長度動態增減。vLLM 改善記憶體管理後，在相同延遲下把吞吐量提高 2–4 倍<Cite k="vllm" />。這類<Term id="inference-engine">推論引擎</Term>軟體，直接決定了推論業者的毛利。

不過批次不能無限加大。批次越大，每位使用者等下一個字的時間通常越長，也就是<Term id="latency">延遲</Term>變差。推論的經濟學，就是在成本、吞吐量與延遲之間找平衡。

### 推論什麼時候超過訓練？

把兩個公式擺在一起，可以算出一個有趣的交叉點：

<MathTeX tex="6ND = 2NT \Rightarrow T = 3D" display label="當推論處理的 Token 數 T 等於訓練 Token 數 D 的 3 倍時，推論累積的運算量就等於訓練" />

也就是說，一個稠密模型在上線後處理的 Token 數，只要超過訓練資料的 3 倍，推論花掉的運算就超過訓練。以 Llama 3 405B 為例，門檻約是 47 兆個 Token。這個量大嗎？Alphabet 在 2026 年 7 月公布的第二季財報中表示，Gemini 模型每分鐘處理 220 億個 API Token<Cite k="goog-q2-2026" />，換算每天約 31.7 兆個，大約 1.5 天就會處理 47 兆個 Token。兩者是不同的模型，這裡只是比較 Token 的數量級：一個熱門模型上線服務幾個月，推論累積的運算量很容易遠遠超過當初的訓練。

推論量這麼大，算力多寡也就直接限制了模型公司能賣出多少服務。OpenAI 財務長 Sarah Friar 在 2026 年 1 月撰文指出，公司營收與可用算力幾乎同步成長：可用算力從 2023 年的 0.2 <Term id="gigawatt">GW</Term> 增加到 2025 年約 1.9 GW，<Term id="arr">年化經常性營收</Term>則從 20 億美元成長到逾 200 億美元<Cite k="oa-business" />。下圖把兩者換算成以 2023 年為 1 的倍數（數字皆為 OpenAI 自行公布）：

同一篇文章也描述了他們的分工：在高階硬體上訓練前沿模型，在成本較低的基礎設施上服務大量的推論工作，讓成本降到每百萬 Token 只要幾美分<Cite k="oa-business" />。

### 價格一路往下掉

推論的單價下降得非常快。Epoch AI 追蹤多項評測後發現，要達到某個固定的能力水準，最便宜的推論價格每年下降 9 倍到 900 倍，依任務而異；例如在博士級科學問題上達到 GPT-4 水準的價格，每年下降約 40 倍。不過最快的降幅集中在最近一年，未必能一直持續<Cite k="epoch-price" />。

降價來自三個方向：硬體（更低精度的運算格式、更大更快的 HBM）、軟體（更好的批次與 KV Cache 管理），以及模型本身（MoE、較小但訓練更久的模型）。但單價下降不代表總帳單變小：<Term id="reasoning-model">推理模型</Term>會先產生大量思考用的 Token 才給出答案，這種<Term id="test-time-compute">推論時運算</Term>讓每個問題消耗的 Token 數大增，詳見<LearnLink id="reasoning-models">推理模型</LearnLink>。

需求不同，晶片也開始分家。Google 第八代 <Term id="tpu">TPU</Term> 分成兩款：8t 為大規模預訓練打造，單一 superpod 有 9,600 顆晶片；8i 則針對<Term id="post-training">後訓練</Term>與推論最佳化，Google 表示它在大型 MoE 模型的低延遲推論上，每美元效能比前代高 80%；截至 2026 年 10 月，兩款在 Google Cloud 網站上仍標示為即將推出<Cite k="google-cloud-tpu" />。微軟的 Maia 200 是專為推論打造的 <Term id="asic">ASIC</Term>，微軟稱它的每美元效能比自家機群中最新一代硬體高 30%<Cite k="ms-maia200" />。

衡量推論硬體的標準，最後都會回到「每個 Token 的成本」。以 Lambda 的隨選價格為例，B200 每 GPU 小時 6.69 美元，比 H100 的 3.99 美元貴<Cite k="lambda-pricing" />；新晶片每小時比較貴，只要每小時產生的 Token 夠多，每個 Token 反而可能更便宜。

<DeepDive title="深入一點：為什麼要把小模型訓練得更久？">

把訓練與推論合起來看，一個模型一生的總運算量約為：

<MathTeX tex="C \approx 6ND + 2NT" display label="總運算量約等於訓練的 6ND 加上推論的 2NT" />

2022 年的 Chinchilla 研究訓練了 400 多個模型，結論是：在固定的訓練預算下，參數量與訓練 Token 數應該等比例放大。依此訓練的 700 億參數 Chinchilla，用和 2,800 億參數 Gopher 相同的運算預算、多 4 倍的資料，表現全面勝出，而且因為模型小，微調與推論都便宜得多<Cite k="chinchilla" />。這就是<Term id="compute-optimal">運算最適化</Term>的概念，也是<Term id="scaling-laws">縮放定律</Term>最常被引用的結果之一。

但 Chinchilla 只最小化公式的第一項。如果預期推論量 T 很大，第二項 2NT 會主導總成本，這時比較省錢的做法是縮小 N、加大 D：多花一點訓練運算，換來之後每個 Token 都更便宜。Sardana 等人把推論成本納入縮放定律後發現，預期推論需求相當大（例如約 10 億次請求）時，就應該訓練比 Chinchilla 最適更小、訓練更久的模型；他們的實驗把每個參數的訓練 Token 數拉到 10,000，模型品質仍在提升<Cite k="sardana" />。

實際的例子是 Llama 3.1 8B：只有 80 億個參數，卻用了約 15 兆個 Token 訓練<Cite k="llama31-card" />，換算每個參數約 1,900 個 Token，遠多於 Chinchilla 的配置。小模型、大資料，正是為了讓推論更便宜。更進一步的技巧，例如量化、推測解碼與分離式推論，見<LearnLink id="inference-optimization">推論最佳化</LearnLink>；縮放定律的細節見<LearnLink id="scaling-laws">縮放定律與運算最適化</LearnLink>。

## 與產業鏈的連結

訓練與推論的帳，決定了錢往產業鏈的哪裡流：

- **訓練帶動「大而集中」的需求** → <SegmentChip id="ai-accelerators" />、<SegmentChip id="networking-optics" />、<SegmentChip id="datacenter-infra" />、<SegmentChip id="energy-power" />：上萬顆 GPU 必須擠在同一個園區同步運作，需要 <CompanyChip id="nvidia" />、<CompanyChip id="amd" /> 的加速器、高速網路，以及 GW 等級的電力與液冷。OpenAI 2025 年的可用算力已達約 1.9 GW<Cite k="oa-business" />。
- **推論帶動「便宜而分散」的需求** → <SegmentChip id="ai-accelerators" />、<SegmentChip id="memory-storage" />：追求每個 Token 的成本，讓雲端業者自研晶片更有吸引力，例如 <CompanyChip id="alphabet" /> 的 TPU 8i、<CompanyChip id="microsoft" /> 的 Maia 200，以及 <CompanyChip id="openai" /> 與 <CompanyChip id="broadcom" /> 合作、規模 10 GW 的自研加速器<Cite k="openai-broadcom" />。Alphabet 也在財報中說明，Google Cloud 的產品營收主要來自銷售 TPU 系統<Cite k="goog-q2-2026" />。Decode 受記憶體頻寬限制，則讓 <CompanyChip id="sk-hynix" />、<CompanyChip id="samsung-electronics" />、<CompanyChip id="micron" /> 的 HBM 更加關鍵。延伸閱讀：<TrendLink id="custom-asic-rise">客製化 ASIC 崛起</TrendLink>、<TrendLink id="inference-chips-new-paradigms">推論專用晶片</TrendLink>。
- **雲端與推論平台** → <SegmentChip id="cloud-neocloud" />、<SegmentChip id="devtools-data-mlops" />：<Term id="hyperscaler">超大規模業者</Term>與 <CompanyChip id="coreweave" />、<CompanyChip id="lambda" /> 等<Term id="neocloud">新雲</Term>按 GPU 小時出租算力；<CompanyChip id="together-ai" />、<CompanyChip id="groq" />、<CompanyChip id="fireworks-ai" />、<CompanyChip id="baseten" /> 等推論平台則按 Token 收費，靠批次處理與推論引擎把成本壓低，賺取中間的差價。
