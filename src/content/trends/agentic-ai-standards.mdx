## 趨勢摘要

一句話：要讓 <Term id="agent">AI Agent</Term> 真正替人做事，它得接上各種工具、資料與其他 Agent。過去每一種組合都要客製整合，現在產業正收斂到幾個開放標準：連接工具與資料的 <Term id="mcp">MCP</Term>、讓 Agent 彼此協作的 <Term id="a2a">A2A</Term>，以及告訴程式 Agent 專案規矩的 AGENTS.md。

**已發生的事實**：<CompanyChip id="anthropic">Anthropic</CompanyChip> 在 2024 年 11 月開源 MCP<Cite k="mcp-launch" />，2025 年 12 月把它捐給 Linux 基金會旗下新成立的 Agentic AI Foundation（AAIF），共同創辦者還有 Block 與 <CompanyChip id="openai">OpenAI</CompanyChip><Cite k="aaif-anthropic" />；<CompanyChip id="alphabet">Google</CompanyChip> 發起的 A2A 也在 2026 年 8 月加入 AAIF<Cite k="a2a-aaif" />。

**仍未定案的部分**：Agent 的身分驗證、授權與支付仍有多套方案並行，哪一套會勝出，目前只能觀察。

## 為什麼重要

Anthropic 發表 MCP 時指出，每接一個新資料來源都要寫一套客製實作，系統很難擴大<Cite k="mcp-launch" />。有了共同協定，工具只要包成一個 MCP 伺服器，就能被所有支援 MCP 的 AI 應用使用；原本 M 個應用乘以 N 個工具的整合工作，變成 M 加 N。標準由誰管理也很重要：Anthropic 表示，把 MCP 交給基金會是為了讓它維持開源、由社群驅動且不偏向特定廠商<Cite k="aaif-anthropic" />。協定保持中立，Agent 生態就比較不會被綁在單一業者的模型或雲端上。

<Callout type="analogy" title="生活化比喻">
MCP 像 USB-C 接頭：週邊廠商只要做一種接頭，任何電腦都插得上。A2A 像電子郵件的通訊規格，不同公司的 Agent 能互相找到彼此、交辦工作。AGENTS.md 則像新人到職時拿到的工作手冊，寫著這個專案怎麼建置、怎麼測試。
</Callout>

## 關鍵驅動力

**一、主要對手一起站台。** AAIF 的白金會員包括 AWS、Anthropic、Block、Bloomberg、<CompanyChip id="cloudflare" />、Google、<CompanyChip id="microsoft">微軟</CompanyChip>與 OpenAI<Cite k="lf-aaif" />。在成立時，公開運作的 MCP 伺服器已逾 1 萬個，ChatGPT、Cursor、Gemini、Microsoft Copilot、VS Code 等產品都已採用<Cite k="aaif-anthropic" />。

**二、分層分工逐漸清楚。**

| 層次 | 標準 | 發起者 | 現況 |
|---|---|---|---|
| Agent 連接工具與資料 | MCP | Anthropic | 2026 年 7 月改為無狀態協定<Cite k="mcp-changelog-2026" /> |
| Agent 之間協作 | A2A | Google | 2026 年 3 月發布 1.0<Cite k="a2a-v1" /> |
| 程式 Agent 的專案說明 | AGENTS.md | OpenAI | 逾 6 萬個開源專案採用<Cite k="lf-aaif" /> |
| Agent 付款 | AP2、ACP | Google；OpenAI 與 <CompanyChip id="stripe" /> | 多套並行<Cite k="ap2" /><Cite k="acp" /> |

A2A 官方的說法是：MCP 是連接內部工具與資料庫的「垂直層」，A2A 是 Agent 對等協作的「水平層」<Cite k="a2a-aaif" />。其中 MCP 等於把模型的<Term id="function-calling">函式呼叫</Term>能力標準化：工具的名稱、參數與回傳格式都有共同規格，任何應用都能用同一套 <Term id="api">API</Term> 格式呼叫。

**三、規格朝大規模部署調整。** MCP 在 2025 年 3 月加入以 OAuth 2.1 為基礎的授權架構<Cite k="mcp-0326" />；2026 年 7 月的新版移除初始化握手與工作階段，任何請求都能送到負載平衡器後的任一台伺服器處理，一級 SDK 每月下載已將近 5 億次<Cite k="mcp-2026" />。A2A 的支持者也持續增加：

<DeepDive title="深入一點：Agent 的身分與授權">
當 Agent 代替使用者呼叫工具，系統要回答兩個問題：這個請求是誰發出的？它被允許做什麼？MCP 在 2025 年 3 月採用 OAuth 2.1 作為授權基礎<Cite k="mcp-0326" />；2026 年 7 月的新版再強化授權流程，例如要求驗證授權伺服器的發行者（RFC 9207），並從動態用戶端註冊轉向以用戶端中繼資料文件識別應用程式<Cite k="mcp-2026" />。NIST 也把 Agent 身分列為研究重點，除了徵求 Agent 安全的公眾意見，還發表了 Agent 身分與授權的概念文件徵求回饋<Cite k="nist-agents" />。簡單說，目標是讓 Agent 的權限可以被追蹤、限制與撤銷，而不是拿著使用者的帳號密碼到處登入。
</DeepDive>

**四、政府開始參與標準。** 美國 NIST 在 2026 年 2 月 17 日啟動 AI Agent 標準計畫，方向包括推動產業主導的標準、支持社群主導的開放協定，以及研究 Agent 的安全與身分<Cite k="nist-agents" />。

## 反方觀點與風險

- **互通性放大安全風險**：同時能讀取私密資料、接觸不可信內容、又能對外傳訊的 Agent，很容易被<Term id="prompt-injection">提示注入</Term>誘導外洩資料；MCP 鼓勵使用者混搭工具，更容易在不知情下湊齊這三項條件<Cite k="simon-trifecta" />。
- **規格仍在變動**：MCP 2026 年 7 月的新版移除了初始化握手與工作階段，並把 Roots、Sampling、Logging 列為不建議使用<Cite k="mcp-changelog-2026" />，既有實作必須遷移。
- **上下文成本**：Agent 接上數千個工具時，光是工具定義就可能佔掉數十萬個 <Term id="token">Token</Term> 的<Term id="context-window">上下文視窗</Term>；在 Anthropic 的範例中，改以程式碼按需載入工具後，Token 用量從 15 萬個降到 2,000 個<Cite k="code-exec" />。
- **支付層尚未統一**：Google 的 AP2 有逾 60 個組織參與<Cite k="ap2" />，Stripe 與 OpenAI 開發的 ACP 則率先在 ChatGPT 上線<Cite k="acp" />，商家可能要同時支援多套協定。

## 觀察指標

- MCP 一級 SDK 的月下載量（2026 年 7 月將近 5 億次）與公開伺服器數量<Cite k="mcp-2026" />。
- A2A 1.0 之後的支持組織數，以及跨雲端、跨 SaaS 的實際生產案例。
- NIST 計畫後續發布的 Agent 安全與身分指引<Cite k="nist-agents" />。
- AP2 與 ACP 是否整合，或由某一套成為主流。
- MCP 舊功能在 2027 年 7 月之後的移除進度，以及 SDK 對新舊版本的相容策略。
