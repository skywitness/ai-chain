一句話：AI 寫程式已從「在編輯器裡幫你補完下一行」，走到「交代一件工作，<Term id="agent">Agent</Term> 自己讀程式庫、修改多個檔案、執行測試，再送出修改」。程式開發也因此成為目前營收最明確的 AI 應用之一。

**已發生的事實**：Anthropic 的 Claude Code 在 2025 年 5 月正式開放，2026 年 2 月年化營收已逾 25 億美元<Cite k="an-series-g" />；Cursor 的年化營收在 2025 年 11 月突破 10 億美元<Cite k="cursor-series-d" />，2026 年 8 月被 SpaceX 以隱含 600 億美元的股票完成收購<Cite k="spacex-8k" />；微軟表示 GitHub Copilot 使用者已達 5,000 萬<Cite k="ms-fy26q4" />。

**仍屬預測的部分**：Gartner 在 2024 年預測，2028 年將有 75% 的企業軟體工程師使用 AI 程式助理，2023 年初還不到 10%<Cite k="gartner-2028" />。至於 AI 能否大幅提高整體軟體產出、會不會減少工程師職缺，目前的證據仍互相矛盾。

## 為什麼重要

程式碼有兩個特性特別適合 AI：結果可以自動驗證（能否編譯、測試有沒有過），而且整個工作流程本來就在電腦裡。這讓模型實驗室能用<Term id="reinforcement-learning">強化學習</Term>大量訓練，也讓 Agent 能自己檢查成果。以修復真實 GitHub 問題的 <Term id="benchmark">Benchmark</Term> SWE-bench Verified 為例，Anthropic 公布的成績在一年多內從三成多升到七成以上：

用量也反映在 <Term id="token">Token</Term> 上。OpenRouter 統計，程式類請求佔平台 Token 量的比例，從 2025 年初約 11% 升到年底部分週次超過五成<Cite k="openrouter" />。Google 執行長早在 2024 年 10 月就表示，Google 逾四分之一的新程式碼由 AI 產生，再經工程師審查接受<Cite k="goog-q3-2024" />。

<Callout type="analogy" title="生活化比喻">
早期的程式助理像會幫你接話的同事：你打半句，它猜後半句。現在的程式 Agent 比較像外包工程師：你開一張工單，它自己翻程式庫、動手修改、跑完測試再交件；你的工作變成把需求寫清楚、審查結果。
</Callout>

<DeepDive title="深入一點：程式 Agent 的工作迴圈">
程式 Agent 的核心其實很單純：模型拿到任務後，反覆「讀檔案、決定下一步、呼叫工具、看結果」，直到測試通過或判斷完成。Anthropic 測 SWE-bench Verified 時，只給 Claude Sonnet 4.5 兩種工具：執行 bash 指令，以及用字串取代的方式編輯檔案<Cite k="an-sonnet45" />。工具這麼簡單，成績高低就主要取決於模型本身會不會規劃、能不能讀懂錯誤訊息再修正。

外加的「鷹架」也有影響。Claude 3.7 Sonnet 在同一組 489 題中，一般設定為 63.7%；若平行產生多個嘗試、丟掉讓既有測試失敗的修改，再用評分模型挑出最好的一個，可提高到 70.3%<Cite k="an-claude37" />。也就是說，程式 Agent 同樣能用更多推論算力換取準確度，代價是更多 Token。產品端則把同一個迴圈搬進不同場景：Claude Code 正式開放時，就支援透過 GitHub Actions 在背景執行任務，並整合 VS Code 與 JetBrains 編輯器<Cite k="an-claude4" />。
</DeepDive>

## 關鍵驅動力

**一、模型能做更長的工作。** Claude Sonnet 4.5 在 SWE-bench Verified 拿下 77.2%，Anthropic 稱觀察到它能在複雜的多步驟任務上持續專注逾 30 小時<Cite k="an-sonnet45" />。<Term id="reasoning-model">推理模型</Term>讓 Agent 能先規劃再動手，詳見<TrendLink id="reasoning-test-time-compute">推理模型與推論時運算</TrendLink>。

**二、產品從補全變成 Agent。** 2024 年 3 月 Cognition 發表 Devin，主打能獨立完成工程任務<Cite k="cognition-devin" />；2025 年 2 月 Claude Code 以命令列工具推出研究預覽<Cite k="an-claude37" />，5 月正式開放<Cite k="an-claude4" />；同月 OpenAI 推出雲端 Codex 研究預覽<Cite k="openai-codex" />。Agent 透過 <Term id="mcp">MCP</Term> 等標準連接外部工具，見<TrendLink id="agentic-ai-standards">Agent 生態與標準化</TrendLink>。

**三、非工程師也開始寫程式。** Andrej Karpathy 在 2025 年 2 月提出「vibe coding」：用自然語言描述需求、幾乎不看程式碼就讓 AI 產生可用的程式，這個詞後來獲選 Collins 英語詞典 2025 年度詞彙<Cite k="wiki-vibe" /><Cite k="collins-woty" />。<CompanyChip id="replit">Replit</CompanyChip>、<CompanyChip id="lovable">Lovable</CompanyChip> 等平台主打這群使用者。

**四、營收與資本快速放大。** 程式工具多以訂閱加 <Term id="token-pricing">Token 計價</Term>收費，<Term id="arr">年化營收</Term>成長極快。Cursor 從 2025 年 1 月逾 1 億美元，6 月逾 5 億美元、11 月破 10 億美元<Cite k="cursor-series-b" /><Cite k="cursor-series-c" /><Cite k="cursor-series-d" />：

## 反方觀點與風險

- **生產力未必如體感**：METR 2025 年的隨機對照試驗中，16 位資深開源開發者處理 246 個真實問題，可用 AI 時反而多花 19% 時間，事後卻仍以為自己快了 20%<Cite k="metr-2025" />。METR 2026 年 2 月表示，現在的工具很可能已帶來加速，但許多開發者不願在沒有 AI 的條件下工作而退出實驗，造成選樣偏誤，因此對加速幅度只能算很弱的證據<Cite k="metr-2026" />。
- **資安缺陷**：Veracode 測試 100 多個模型，45% 的程式碼樣本未通過資安測試，帶入 OWASP Top 10 類型的漏洞<Cite k="veracode" />。Agent 能執行指令，也讓<Term id="prompt-injection">提示注入</Term>的後果更嚴重。
- **信任度低**：Stack Overflow 2025 年調查中，不信任 AI 輸出準確度的開發者（46%）多於信任者（33%）<Cite k="so-2025" />。
- **供應商即對手**：程式工具依 Token 向模型業者付費，而模型業者也推出 Claude Code、Codex 等直接競品，工具商的毛利與議價力受壓。
- **就業衝擊**：史丹佛數位經濟實驗室以 ADP 薪資資料發現，AI 暴露度高的職業中，22–25 歲年輕員工的就業比對照情境低 19%；作者強調這是描述性指標，不是因果估計<Cite k="stanford-canaries" />。
